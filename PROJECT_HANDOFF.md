# UltraExplorer — состояние проекта

Обновлено: 2026-08-29.

## 1. Что это

Нативный файловый менеджер Windows: оболочка Windows 11 File Explorer вокруг
бесконечного ZUI-холста вместо одномерного списка.

- `.NET 10`, WPF, Windows x64.
- `Nodify 7.3.0` — ZUI/node canvas (pan, zoom, selection, connections, minimap).
- Никаких других зависимостей: Shell-интероп написан напрямую (Vanara убрана,
  см. §6).

Решение: `UltraExplorer.sln`. Приложение: `src/UltraExplorer/UltraExplorer.csproj`.
Сборка, запуск, тесты и publish — в [BUILD.md](BUILD.md).

## 2. Режим View all

- каждый готовый диск — отдельный корень; WSL-дистрибутивы и UNC добавляются
  как дополнительные корни и восстанавливаются из workspace;
- одна вершина графа = один объект файловой системы (диск, папка, файл);
- раскрытие ленивое, ровно на один уровень, потомки никогда не сканируются
  заранее; лимит 5 000 непосредственных детей, дальше `…` Load more;
- reparse point не раскрывается автоматически (значок-бейдж на узле);
- одновременно может быть раскрыто сколько угодно ветвей и дисков.

### Раскладка

Дерево растёт **сверху вниз**: родитель над **блоком** своих детей. Ряд растёт
линейно с числом детей — папка на 5 000 записей давала линию длиной под миллион
единиц. Блок растёт как корень из числа: та же папка — примерно 64 на 79.

Число колонок берётся из целевой пропорции (блок примерно вдвое шире, чем выше),
папка до 12 записей остаётся одной строкой. Блок резервируется **целиком одним
запросом** к пространственному индексу: сначала под родителем, при помехе — на
колонку вбок, потом на строку вниз. Только если целиком не влезает нигде,
каждый ребёнок ищет место сам.

Позиции, поставленные вручную, — якоря: их обходят и они переживают refresh и
перезапуск. Автоматические позиции **не восстанавливаются** из сохранённого
рабочего пространства, а считаются заново, иначе изменение раскладки никогда бы
не дошло до уже существующего холста. Обновление ветки (F5) при этом ничего не
двигает: позиции, записанные в этой же сессии, восстанавливаются как есть.

Команда **Tidy the layout** в меню холста сбрасывает вообще все позиции, включая
ручные, и раскладывает дерево заново.

### Цвет ветки

У каждой папки свой оттенок, выведенный из её пути (FNV-1a, поэтому он один и
тот же от запуска к запуску). Им рисуются все линии, выходящие из этой папки, и
полоска слева у каждого её ребёнка. Пока дети были одной строкой, одного цвета
хватало; у блока линии идут друг над другом, и без цвета не видно, какая чья.
С глубиной оттенок темнеет, поэтому верхние уровни читаются первыми.

Размер узла падает с глубиной **геометрически**: каждые 8 уровней вдвое, и
перестаёт уменьшаться на 32-м.

| Глубина | Размер |
|---:|---:|
| 0 | 100% |
| 8 | 50% |
| 16 | 25% |
| 24 | 12.5% |
| 32 и глубже | 6.25% |

Промежутки между узлами масштабируются вместе с узлом, поэтому глубокая ветвь
остаётся компактной, а не тонет в пустоте. Раскладка инкрементальная: раскрытие
ветви не двигает уже размещённые узлы, а вручную перетащенный узел остаётся на
месте даже после refresh.

### Уровни детализации (mip)

| Зум | Уровень | Что рисуется |
|---:|---|---|
| < 6% | Cluster | занятые области как блоки плотности |
| 6–15% | Dot | плашки, без ветвей |
| 15–30% | Glyph | плашки и ветви |
| 30–62% | Compact | настоящие узлы: иконка и имя |
| ≥ 62% | Detailed | плюс метаданные и бейджи |

Ниже 30% граф рисуется не контролами, а несколькими пакетными геометриями в
координатах графа, так что панорама и зум — это только смена
`RenderTransform`: уже загруженный визуал двигает композитор, ничего не
перезаписывается. На самом дальнем уровне занятые ячейки сетки сливаются в
блоки, и стоимость зависит от сетки, а не от числа узлов.

## 3. Оболочка

Сетка окна: title/tab 40, navigation 48, command bar 44, content `*`,
status bar 24. Верхние три строки на всю ширину.

- Title/tab: одна вкладка 34 высотой, caption buttons 46 × 40, close hover
  `#C42B1C`. `WM_NCHITTEST` возвращает `HTMAXBUTTON` над Maximize, поэтому
  Windows 11 показывает Snap Layouts.
- Navigation: Back/Forward/Up 32 × 32, breadcrumb-сегменты с переходом в
  editable path по `Ctrl+L` или клику, Refresh справа внутри, поиск 300
  (min 220 / max 360).
- Command bar: `Organize ▾`, `Give access to ▾`, `New folder`, разделитель,
  segmented toggle `View all | View select`, справа collapse-all, canvas
  options, pane toggle, overflow.
- Navigation pane: Home; divider; Desktop, Downloads, Documents, Pictures,
  Music, Videos, закреплённые; divider; This PC и диски; divider; Network и WSL.
- Status bar: слева количество/выделение, по центру путь, справа две кнопки вида.

Поиск рекурсивный, обходом в ширину, результаты приходят потоком по мере
нахождения (до 200), reparse points пропускаются.

Цветовые метки и заметки хранятся по пути, а не по узлу, поэтому переживают
закрытие ветви и перезапуск.

## 4. Файловый диалог для чужих программ

Другая программа может попросить UltraExplorer выбрать за неё файл или папку.
Окно то же самое — холст, боковая панель, крошки, поиск — плюс подвал
диалога: **File name**, **Files of type**, кнопка действия, Cancel.

Реализован набор `IFileDialog` из `shobjidl_core.h` целиком, плюс перевод
`OPENFILENAME.Flags` и `BROWSEINFO.ulFlags` — вызывающему не нужно переписывать
маску, которая у него уже есть. Полный контракт: [PICKER.md](PICKER.md).

Два входа:

- `UltraExplorer.exe --pick …` — любой язык; ответ идёт кодом возврата,
  JSON-файлом и в родительскую консоль;
- COM: собственный CLSID → `IFileOpenDialog` / `IFileSaveDialog`. Регистрация
  только для текущего пользователя, `--register-picker`.

Системный `CLSID_FileOpenDialog` намеренно **не** подменяется: он зарегистрирован
как `InProcServer32` на `shell32.dll`, и COM при `CLSCTX_ALL` всегда предпочтёт
in-proc сервер записи `LocalServer32`. Подмена потребовала бы своей нативной DLL
в каждом процессе.

Фильтр типа файла применяется **на чтении каталога**, а не после него: узлы для
неподходящих файлов вообще не создаются. Папки не фильтруются никогда — через них
пользователь добирается до того, что подходит.

Поле имени ведёт себя как в стандартном диалоге: `*.log` перестраивает вид,
`C:\logs\*.txt` переходит и фильтрует, имя папки открывает её, `"a" "b"` — это
два файла, `%WINDIR%` разворачивается, а при сохранении имя без расширения
получает его от типа файла.

### Скрытые ветки

Папку можно убрать с холста целиком — пункт **Hide from canvas** в контекстном
меню узла (он добавлен прямо в нативное меню Explorer) или `Ctrl+H`. Это не то
же самое, что свернуть: узел исчезает вместе с поддеревом **и освобождает место**
— скрытые узлы уходят из пространственного индекса, поэтому следующая раскладка
занимает их площадь. Список скрытого и «Show all hidden» — в меню пустого холста;
состояние хранится по путям в рабочем пространстве и переживает refresh,
переоткрытие ветки и перезапуск.

## 7. Что исправлено по ходу

- **Heap corruption `0xC0000374`.** Обёртка над Shell-меню сама владела PIDL и
  `IContextMenu` и освобождала их повторно. Меню переписано на прямой COM с
  явным временем жизни; `IContextMenu2/3` — это те же RCW, что и
  `IContextMenu`, и их отдельное освобождение само по себе было double free.
  Зависимость Vanara удалена целиком.
- **Панорама не обновляла холст.** Nodify шлёт `ViewportUpdated` только при
  зуме и ресайзе, поэтому при панораме culling и пакетный слой оставались на
  старом вьюпорте. Добавлена подписка на `ViewportLocation`.
- **Клик по холсту убивал клавиатуру.** `Keyboard.ClearFocus()` оставлял окно
  без фокусируемого элемента, и все сочетания, кроме Alt-овых, молча
  переставали работать. Теперь фокус уходит на холст.
- **`Ctrl` отменял панорану средней кнопкой.** `MouseGesture` совпадает ровно с
  одной комбинацией модификаторов; теперь привязаны все.
- **Раскрытие большой папки вешало UI.** `SHGetFileInfo` вызывался синхронно на
  каждый созданный узел. Иконки резолвятся в фоне и только для узлов на экране.
- **`Key.System`.** WPF отдаёт `F10` и все `Alt`-сочетания через `SystemKey`,
  поэтому `Alt+←/→/↑`, `Alt+Enter` и `Shift+F10` молча не работали.
- **Приоритет значений в XAML.** Локально заданные `Visibility`, `Height`,
  `Background` перебивали Style-триггеры: Dot-уровень не рисовался, диск не был
  выше папки, выделение не подсвечивало плашку.
- **Drag показывал Move, а делал Copy** — теперь курсор и операция берут
  решение из одного `MainViewModel.ShouldMove`.
- **Буфер обмена** писал собственный сериализованный формат, которого на
  .NET 9+ уже нет: только `CF_HDROP` и `Preferred DropEffect`, как у Explorer.
- **Shell-операции** шли на background-потоке, убиваемом при выходе.
- **Отмена** диалога копирования/удаления рапортовалась как успех.
- **`Delete` без выделения** отправлял в корзину папку, на которую просто
  смотрят.
- Дополнительные корни (WSL/UNC) не сохранялись; reset zoom дёргал вид; поиск
  ждал полного обхода диска.
- **Клик по холсту ниже 30% зума не делал ничего.** Обработчик висел на
  всплывающем `MouseLeftButtonDown`, а к этому моменту Nodify уже начал своё
  выделение рамкой, пометил событие обработанным и захватил мышь — то есть
  обработчик не вызывался вовсе. Плюс он был закрыт проверкой
  `e.OriginalSource != Editor`, которая никогда не проходит: клик приходит на
  Border внутри шаблона редактора. Перенесено в туннельное событие.
- **Окно вылезало за рабочую область в развёрнутом виде.** Рамка изменения
  размера у окна без заголовка остаётся, поэтому Windows разворачивает его
  больше рабочей области на ширину рамки с каждой стороны, а WindowChrome потом
  обрезает вылезшее регионом — верх кнопок заголовка и низ строки состояния
  просто срезались. Добавлен `WM_GETMINMAXINFO` с ограничением по монитору.
  Измерено: было 7/7/55/7 px вылета, стало 0/0/0/0.
- **Чёрный прямоугольник во время перетаскивания.** Nodify кэширует контейнеры в
  один bitmap ниже порога зума; при минимальном зуме 6% это диапазон 30–56% —
  ровно там, где приложение ещё рисует настоящие контейнеры, — а размер
  поверхности равен вьюпорту, делённому на зум. Оптимизация выключена: у
  приложения есть своё отсечение и пакетный слой.
- **Диалог открывался не там, куда просили.** Восстановление рабочего
  пространства выделяло папку из прошлой сессии, и это перетирало запрошенную
  папку **до** того, как окно к ней переходило. Стартовая папка теперь
  запоминается до постройки холста.
- **Скрытый участок пути обрывал переход.** `AppData` скрыт, поэтому переход в
  папку под ним останавливался на профиле. Названный по имени объект теперь
  материализуется независимо от фильтров отображения — так же ведёт себя
  адресная строка Explorer.
- **COM: вызовы приходили не на тот поток.** Управляемый CCW агилен, поэтому
  вызов попадает на произвольный RPC-поток, а не на STA окна. Работа с окном
  уходит в диспетчер, а чтения отвечают по снимкам.
- **COM: обратный вызов вешал обе стороны.** Колбэк, отправленный с UI-потока,
  для однопоточного клиента — чужая причинность, и COM ставит его в очередь до
  освобождения клиента, которое не наступит. Колбэки теперь исполняет тот поток,
  которому COM отдал вызов.
- **Save-диалог не мог вернуть новый файл.** `SHCreateItemFromParsingName`
  работает только для того, что уже существует. Несуществующее имя строится
  через `IFileSystemBindData` — механизм самого шелла.
- **COM-сервер не завершался.** Считать объекты по финализаторам бессмысленно:
  закрытое окно надолго остаётся достижимым. Сервер держит по одной ссылке на
  выданный объект и смотрит на счётчик самого CCW.
- Доступность: `AutomationProperties.Name` на всех иконочных кнопках и узлах,
  focus visual вместо `FocusVisualStyle = null`, тёмный текст на светлом
  акценте, собственный шаблон ScrollBar, Cancel — кнопка по умолчанию в диалоге
  удаления.

## 8. Известные ограничения

- Multi-select контекстное меню нативное только когда все элементы лежат в
  одной папке — так его строит сам Shell. Для разнородного выделения
  показывается собственное меню приложения.
- Живое обновление подписано только на активную папку (один watcher).
  Переименование родителя открытой ветви снаружи требует `F5`.
- Cross-volume drop по умолчанию Copy; Move — по `Shift`.
- Ниже 30% зума узлы не кликаются как контролы; вместо этого клик по холсту
  попадает по графу через пространственный индекс и выделяет ближайший узел.
- `View select` не реализован.
- В файловом диалоге не реализован `IFileDialogCustomize`: `QueryInterface`
  честно отвечает `E_NOINTERFACE`, а не подсовывает пустышку.
- `IFileSaveDialog` не редактирует метаданные: property-store методы отвечают
  `E_NOTIMPL`, чтобы вызывающий мог записать свойства сам.
- Из `IFileDialogEvents` не шлются `OnFolderChanging` и `OnShareViolation`.
