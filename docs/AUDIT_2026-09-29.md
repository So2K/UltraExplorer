# Аудит UltraExplorer — 29 сентября 2026

Windows-версия имеет работающее ядро, согласованный интерфейс и хорошую скорость холста. Переписывать её целиком оснований нет. Перед следующим релизом стоит исправить операции создания/вставки файлов и сохранение состояния нескольких экземпляров, а затем подключить реальные проверки к выпуску. Локальный Avalonia-порт пока нельзя выпускать с заявленной поддержкой Windows: обычное удаление там безвозвратно.

## Что именно проверено

- GitHub: [So2K/UltraExplorer](https://github.com/So2K/UltraExplorer), ветки, последние изменения, все доступные issues/PR, релизы и последние Actions.
- На GitHub `main` и релиз v1.1.0 соответствуют `0829a6288cca55d260a6ed9a7b84ae5435f23ad8`. Локальный HEAD — `59ee1c2`. Сравнение Git blob показало, что 236 отслеживаемых файлов совпадают с GitHub, кроме двух файлов иконки. Поэтому найденные проблемы основного кода применимы и к GitHub-версии.
- Другая ветка `claude/festive-lamport-v5lkr7` содержит другой вариант кода: в ней отсутствуют текущие split view и новый поисковый слой. Её нельзя принять за готовое исправление текущего `main` без отдельного сравнения реализации.
- Локальные изменения BUILD.md, PROJECT_HANDOFF.md, LINUX.md, Linux-решение, Avalonia-проект и tests/UltraSmoke учитывались отдельно. Avalonia-порт отсутствует в проверенном GitHub `main` и в релизе v1.1.0.
- Проверены архитектура чтения/раскладки и GPU/CPU-рендеринга, выделение и две панели, файловые операции, поиск, наблюдение за изменениями, сохранение состояния, picker/COM, сборка, установщик и CI. Основной акцент — пользовательские сценарии и места, где можно потерять данные или получить ложное сообщение об успехе.
- Windows-сборки Debug и Release; самостоятельная Release-сборка Avalonia-проекта; полные и выборочные smoke-прогоны; дополнительные воспроизведения найденных дефектов на созданных для аудита файлах; встроенный GPU-бенчмарк и снимки интерфейса.

Это аудит проверенного снимка проекта, а не гарантия отсутствия остальных ошибок. Реальный Linux/macOS, SMB с обрывами связи, RDP и живой диалог сторонней COM-программы в этом окружении не проверялись. Основной код и существующие пользовательские изменения не исправлялись.

## Подтверждённые проблемы основной Windows-версии

### W1. Вставка копии в ту же папку ничего не делает, но выглядит успешной — P2

**Сценарий:** выбрать файл, Ctrl+C, Ctrl+V в той же папке. Пользователь ожидает вторую копию с новым именем.

`NativeShellService.CopyOrMoveAsync` исключает источники, у которых исходный и целевой путь совпали, независимо от `move`. Для копирования это лишает пользователя стандартного сценария дублирования через буфер. `MainViewModel.TransferAsync` затем сообщает число переданных элементов из исходного списка; фактического результата операции у него нет. При cut/paste в собственную папку возможно также снятие выделения без переноса.

**Воспроизведено:** после `CopyOrMoveAsync([document.txt], его_папка, false)` осталось ровно одно имя `document.txt`. Метод вернул успех.

**Код:** [NativeShellService.cs:239](E:/AiControl/UltraExplorer/src/UltraExplorer/Services/NativeShellService.cs:239), [MainViewModel.cs:1254](E:/AiControl/UltraExplorer/src/UltraExplorer/ViewModels/MainViewModel.cs:1254).

**Исправление:** для copy в собственную папку использовать уже имеющуюся логику имени копии; для move сообщать, что перенос не нужен. Возвращать результат с выполненными/пропущенными элементами и строить toast по нему. Новая библиотека здесь не нужна.

### W2. Имя нового текстового файла может вывести создание за пределы выбранной папки — P2

**Сценарий:** в New text file ввести `..\outside-created.txt` или абсолютный путь.

`CreateNoteFile` не проверяет недопустимые символы имени и разделители, как это делают соседние `CreateFolder`/`Rename`. `Path.Combine` допускает переход в родителя и абсолютный второй аргумент.

**Воспроизведено:** выбран `chosen-folder`, имя `..\outside-created.txt`; файл появился в родительской папке. Это дефект валидации поля имени, а не обход границы прав доступа ОС.

Кроме того, `File.WriteAllText(target, string.Empty)` открывает файл с усечением. Проверка `File.Exists` до записи не защищает от файла, созданного другим процессом между проверкой и записью. Возможность такого усечения следует из кода; отдельная гонка с потерей содержимого не воспроизводилась.

**Код:** [NativeShellService.cs:355](E:/AiControl/UltraExplorer/src/UltraExplorer/Services/NativeShellService.cs:355), [NativeShellService.cs:372](E:/AiControl/UltraExplorer/src/UltraExplorer/Services/NativeShellService.cs:372).

**Исправление:** единая проверка имени для create/rename и `FileMode.CreateNew` с повторным подбором имени при коллизии. В Avalonia-порте создание нового файла уже использует CreateNew — это подходящая локальная реализация для переноса обратно.

### W3. Два экземпляра приложения конфликтуют при сохранении workspace — P2

У `WorkspaceStore` семафор принадлежит экземпляру сервиса, а временный путь у всех одинаков: `workspace.json.tmp`. Два процесса или два отдельных сервиса не разделяют этот семафор. В App нет механизма единственного экземпляра.

**Воспроизведено:** два отдельных `WorkspaceStore`, одновременно сохраняющих в один путь, получили IOException о занятом `workspace.json.tmp`. Это показывает конфликт самого хранилища; два видимых окна для воспроизведения не запускались.

Даже после устранения общего временного имени останется вопрос семантики: закрывшееся позже окно может записать старые избранное и настройки поверх более свежих изменений другого окна. На закрытии ошибка сохранения только попадает в crash.log, окно закрывается.

**Код:** [WorkspaceStore.cs:107](E:/AiControl/UltraExplorer/src/UltraExplorer/Services/WorkspaceStore.cs:107), [MainWindow.xaml.cs:300](E:/AiControl/UltraExplorer/src/UltraExplorer/MainWindow.xaml.cs:300).

**Исправление:** уникальный временный файл, как уже сделано в ViewAllWorkspaceStore, плюс явная модель нескольких окон: один процесс с общим состоянием либо синхронизация изменений между процессами. Одного уникального .tmp недостаточно для защиты от записи устаревшего состояния.

### W4. Downloads задан жёстким путём и игнорирует перенос системной папки — P2

Боковая панель берёт `UserProfile\Downloads`. Если пользователь перенёс «Загрузки» на D: через свойства системной папки, приложение покажет старую папку или уберёт пункт, если старой папки нет. Это подтверждено чтением кода; на текущей машине Downloads не перенесён, настройки ОС для эксперимента не менялись.

**Код:** [FileSystemService.cs:27](E:/AiControl/UltraExplorer/src/UltraExplorer/Services/FileSystemService.cs:27).

**Исправление:** получать путь через Windows Known Folder API для Downloads, как остальные специальные папки получаются через системные API.

## Проверки и выпуск

### Q1. Зелёный Actions не означает прохождение проверок — P1

В workflow есть `dotnet build` приложения и ViewAllSmoke, затем publish/installer/release. Исполняемый файл ViewAllSmoke не запускается. На GitHub последние сборки успешно завершены, но это подтверждает сборку и упаковку, а не работоспособность сценариев.

**Источник:** [release.yml](https://github.com/So2K/UltraExplorer/blob/0829a6288cca55d260a6ed9a7b84ae5435f23ad8/.github/workflows/release.yml#L52), [последний релизный run](https://github.com/So2K/UltraExplorer/actions/runs/36561391631).

**Исправление:** запуск обязательных функциональных проверок до упаковки и релиза; сохранять лог при ошибке. Нужны подготовленная временная папка и явные правила для проверок, зависящих от Everything/GPU/скорости машины. Функциональные проверки и измерения производительности лучше выполнять отдельными этапами с соответствующим окружением.

### Q2. Smoke не проходит по опубликованной инструкции с обычным Windows TEMP — P2

Fixture создаётся под `%TEMP%`, обычно в скрытом AppData. В `PickerGraphRules` helper Reveal ищет путь через перечисление предков при выключенном IncludeHidden; скрытый предок отсутствует в графе. Далее `node!` вызывает NullReferenceException и прекращает остальные группы.

**Воспроизведено дважды:** полный запуск и отдельный `--only PickerGraphRules` с обычным TEMP остановились одинаково. С видимой временной папкой группа проходит.

**Код:** [Program.cs:37](E:/AiControl/UltraExplorer/tests/ViewAllSmoke/Program.cs:37), [PickerChecks.cs:529](E:/AiControl/UltraExplorer/tests/ViewAllSmoke/PickerChecks.cs:529).

**Исправление:** добавить fixture напрямую как корень либо использовать адресное раскрытие, которое не зависит от скрытых предков. После отрицательной проверки не разыменовывать null. Интеграцию с живой машиной не смешивать с проверкой собственно правил диалога.

### Q3. Бюджеты массового выделения не выполняются в этом окружении — P2

Два полных прогона и отдельная проверка дали разные результаты, но Ctrl+A повторно вышел за бюджет 8 мс: 10,6 и 11,2 мс. Отдельная проверка загрузки путей получила 3,56 мс при бюджете 3 мс. Функциональная часть выполняется.

**Код:** [NestedSelectionChecks.cs:1225](E:/AiControl/UltraExplorer/tests/ViewAllSmoke/NestedSelectionChecks.cs:1225), [NestedSelectionChecks.cs:1283](E:/AiControl/UltraExplorer/tests/ViewAllSmoke/NestedSelectionChecks.cs:1283).

**Исправление:** измерить массовое обновление selection и передачу списков путей, исключить повторные проходы и лишние уведомления. Для автоматического сравнения скорости зафиксировать конфигурацию и прогрев; не просто повышать бюджет, чтобы сделать тест зелёным.

## Локальный Avalonia-порт: отдельные проблемы

### L1. Обычный Delete на Windows уничтожает файлы без корзины — P1

`DeleteAsync(..., permanently: false)` всё равно вызывает DeleteOutright, если `IsWindows`. UI в MainViewModel при этом пишет «Moving to Recycle Bin…», затем «Moved to Recycle Bin». Для пользователя обычное удаление превращается в безвозвратное без предусмотренного предупреждения.

**Воспроизведено на двух собственных тестовых файлах:** первый файл исчез из исходной папки; каталога пользовательской корзины порта не появилось. WPF-версия использует другой сервис и этим результатом не затрагивается.

**Код:** [NativeShellService.cs:532](E:/AiControl/UltraExplorer/src/UltraExplorer.Linux/Services/NativeShellService.cs:532), [MainViewModel.cs:909](E:/AiControl/UltraExplorer/src/UltraExplorer.Linux/ViewModels/MainViewModel.cs:909).

**Исправление:** на Windows подключить уже работающий Shell-механизм основной версии или запретить обычное удаление до появления корзины. Уничтожение допустимо только по явно выбранной пользователем операции permanent delete.

### L2. Ошибка при переносе каталога в корзину оставляет перемещённую часть без записи восстановления — P1

Для переноса на другой том `TransferDirectory` переносит содержимое по одному элементу. После первого успешно перемещённого файла второй может дать ошибку. Обработчик в TrashEntry удаляет `.trashinfo` при любой ошибке, хотя часть содержимого уже лежит в корзине, а исходной папке её уже нет.

**Воспроизведён общий алгоритм на Windows через прямой вызов приватного TrashEntry:** исходник на E:, тестовая корзина на C:, два файла, второй удерживается открытым. После ошибки: `TRASH_ORIGINAL_FIRST_EXISTS=False`, `TRASH_MOVED_FIRST_EXISTS=True`, `TRASH_RECORD_EXISTS=False`. Байты первого файла сохранились, но обычное восстановление через запись корзины больше невозможно. Реальный Linux-десктоп отдельно не запускался.

**Код:** [NativeShellService.cs:744](E:/AiControl/UltraExplorer/src/UltraExplorer.Linux/Services/NativeShellService.cs:744), [NativeShellService.cs:1004](E:/AiControl/UltraExplorer/src/UltraExplorer.Linux/Services/NativeShellService.cs:1004).

**Исправление:** прежде всего использовать корзину на том же файловом разделе. Для неизбежного переноса между томами — сначала полностью копировать в staging, проверять результат, и только потом удалять исходник. При частичном переносе сохранять запись и сведения о частичном результате, а не удалять единственный путь к восстановлению.

### L3. Команда сборки Linux-решения не работает — P1 для выпуска порта

В решении объявлен `tests/UltraSmoke/UltraSmoke.csproj`, но файла нет. В папке есть только AddressChecks.cs и FolderListChecks.cs; отсутствует и полноценная точка входа тестового проекта. Команды build/test из LINUX.md сейчас невоспроизводимы. Отдельный проект приложения собирается.

**Код:** [UltraExplorer.Linux.sln:14](E:/AiControl/UltraExplorer/UltraExplorer.Linux.sln:14), [LINUX.md:42](E:/AiControl/UltraExplorer/LINUX.md:42).

### L4. Документация обещает больше платформ и функций, чем реализовано — P2

В порте нет текущего NestedCanvas/NestedTree и split view. Основной продукт на GitHub по умолчанию использует вложенный холст; порт показывает дерево. Это важное различие продукта, которое нужно явно указать или устранить.

macOS заявлена в BUILD.md/LINUX.md, но `NativeShellService.Open` после проверки Windows использует Linux-маршруты xdg-open/gio/.desktop. Отдельного открытия через macOS `open`/LaunchServices нет. На типичной macOS без этих Linux-команд метод не имеет подходящего обработчика. Это вывод из кода, не проверка на настоящем Mac.

Порт хранит Windows workspace в той же папке, что и WPF-версия, при этом его старый WorkspaceStore не имеет карантина повреждённого JSON и сериализации параллельных записей. Поэтому уже выполненные исправления основной версии нужно переносить в порт системно.

## UX: что улучшить без изменения задумки и палитры

1. **Кнопка «+» рядом с единственной вкладкой выглядит как создание вкладки, но вызывает FitAll.** Tooltip уточняет действие, однако визуальное ожидание остаётся другим. Использовать явную иконку сброса/общего вида; настоящие вкладки — отдельная функция. [MainWindow.xaml.cs:1538](E:/AiControl/UltraExplorer/src/UltraExplorer/MainWindow.xaml.cs:1538).
2. **Убрать неработающий View select до реализации.** Постоянно выключенная половина главного переключателя создаёт ощущение незавершённости. [MainWindow.xaml:594](E:/AiControl/UltraExplorer/src/UltraExplorer/MainWindow.xaml:594).
3. **Объяснить область фильтра.** Canvas-фильтр видит только прочитанные папки, а Search ищет по дискам. Маленькая подсказка области действия в фильтре и переход к поиску помогут не принять отсутствие подсветки за отсутствие файла.
4. **Числовая сортировка имён.** Сейчас folder 10 идёт раньше folder 2. В .NET 10 уже есть [CompareOptions.NumericOrdering](https://learn.microsoft.com/en-us/dotnet/api/system.globalization.compareoptions?view=net-10.0#fields), поэтому отдельный самописный natural-sort парсер не нужен. Нужно сохранить согласованность сортировки и бинарного поиска по именам: сырые списки и их индексы нельзя перевести на разные компараторы.
5. **Отмена операции внутри приложения.** Shell сохраняет undo для Explorer, но в самом UltraExplorer нет обработчика Ctrl+Z. Для полноценной замены проводника нужна понятная отмена доступных действий или хотя бы явное объяснение восстановления. Это отсутствующая функция, а не утверждение, что существующая корзина WPF сломана.
6. **Доступность холста.** Chrome получает AutomationProperties, а отдельные GPU-ячейки не представлены как элементы UI Automation. Проверку screen reader и удобный переход в обычный список стоит включить в приёмку. В этом аудите screen reader не запускался.
7. **Русская локализация и масштаб текста.** Сейчас язык установщика можно выбрать, основные подписи приложения заданы по-английски. Локализацию, длинные имена и крупный системный шрифт проверять на сохранение текущей сетки и палитры.
8. **Срезанные большие каталоги.** Nested ограничивает отображение 50 000 файлов, Tree первоначально — 5 000 записей. Счётчики и предупреждения есть, но при сортировке урезанного набора нельзя обещать пользователю глобально первый/самый новый файл каталога. Предлагать открыть полный список и документировать пределы обоих режимов.

## Что в проекте уже сделано хорошо

- Ленивое чтение, очереди с приоритетами и бюджеты кадра подходят этому продукту; измерения поддерживают выбор GPU-рендеринга.
- Есть CPU-fallback и проверки GPU/атласов/текста, а не только тесты моделей.
- Результат поиска раскрывается точно, чтобы исчезнувший файл не заменялся выделением его папки с последующим опасным Delete.
- Основная Windows-версия не сохраняет не восстановленный граф поверх предыдущего состояния; повреждённые state-файлы откладываются в карантин.
- Полные списки файлов и canvas используют общий selection; split view проверяет навигацию, переключение активной панели и операции между панелями.
- Основные copy/move/delete передаются Windows Shell, а не реализованы простым рекурсивным удалением.
- По просмотренным снимкам основная палитра и оболочка согласованы; визуальную концепцию имеет смысл сохранять.

## Предлагаемый порядок работ

**До следующего Windows-релиза:** W1–W3, рабочий smoke и запуск функциональных проверок в CI. Добавить точечные регрессии для вставки в собственную папку, двух хранилищ состояния и имени с разделителем. W4 также небольшой самостоятельный фикс.

**Затем доводка UX:** неоднозначный «+», отключённый View select, область фильтра, числовая сортировка, понятное восстановление действий. После этого — локализация, доступность, проверки 150–200% DPI и больших имён. Новые вкладки и режим оценки занятого места — отдельные продуктовые решения, не обязательное условие исправления нынешних дефектов.

**Перед выпуском порта:** сначала L1/L2 и воспроизводимые build/test, затем перенос уже работающих Nested/split и исправлений state/navigation/watch. Пока это не сделано, описывать порт как незавершённый Linux-вариант, а поддержку Windows/macOS — только в пределах реально проверенных сценариев.

Готовые решения в этом случае уже находятся в проекте и стандартных API: CreateNew, уникальные временные файлы, Windows Shell, Known Folder API, NumericOrdering. Подключение нового большого файлового менеджера целиком заменило бы характерный холст и создало бы больше работы, чем исправление этих конкретных подсистем. Общие правила путей, selection, сортировки и сохранения стоит вынести в платформенно независимый слой, чтобы порт не терял исправления Windows-версии.
