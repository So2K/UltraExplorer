## Systemic themes

1) UI-thread I/O is the main source of hangs. Disk, SMB and COM calls run synchronously on the one shared WPF dispatcher: Directory.Exists, DriveInfo.IsReady, SHParseDisplayName, FindFirstFile, File.Exists filters over large selections, and ShellWindows registration. All windows in the resident process, including Explorer-replacement windows, share that thread, so one unreachable share or mapped drive freezes everything. In the dialog worker the same stall stops the heartbeat, and the guardian then turns off the whole integration. The fix pattern exists already (RefreshDrivesAsync, FindStaleAsync, IconExtractor's watchdog) but is applied unevenly.
2) The integration fails closed too readily. Many transient conditions persist Enabled=false, which also removes the Run entry and restores the Explorer verbs: a sleep/resume heartbeat gap, a tray-icon failure at logon, a settings-lock timeout, UIA capture errors, a text longer than 2048 characters, a sharing-violation on File.Move, a missing SEM_FAILCRITICALERRORS. A single recoverable glitch silently switches off a feature the user chose.
3) Shared state across processes and windows is written as whole snapshots: folder-marks.json, workspace.json fields, pins, and per-GUID shell-windows stores. Nothing tracks or merges changes, and nothing reloads, so the main window, the prepared picker, COM pickers, second instances and adopted windows erase each other's edits. Per-window GUID stores are never read again or cleaned up.
4) Path identity is inconsistent. GetFullPath/Normalize strips trailing dots and spaces. Lookups ignore case in case-sensitive (WSL) folders. The raw reparse attribute is treated as 'link' for OneDrive placeholders. \\\\?\\ is applied only to drive paths. As a result, navigation, selection and file operations can address a sibling item, and by-name materialization disagrees with the directory reader.
5) Unguarded FILETIME conversion. NestedDirectoryReader handles out-of-range times, but FolderWalk, ViewAllFileSystemService (GetChildrenAsync, Describe, DescribeDirectoryAsync) and BuildSecondaryText do not. The result ranges from a process crash (already seen in crash.log) to stale lists and folders that cannot be opened.
6) Selection semantics are unsafe for destructive commands. Navigation selects the destination folder, refreshes fall back to selecting the parent, additive gestures keep the container, Ctrl+A uses a stale CurrentFolder, filters keep invisible items selected, and the list anchor is never passed on. Delete, Cut and Move then act on whole folders or on items the user cannot see.
7) The broker/router acknowledges before acting. Forwarders exit 'accepted' before the destination UI has done anything, so closing windows, a hung UI, superseding tickets, oversize packets and bare-process bootstraps lose folder opens or create stray windows. There is no AllowSetForegroundWindow hand-off, and Explorer restarts leave dead ShellWindows proxies.
8) Live-update gaps. Registration happens only after apply, partial ancestors are never registered, and Gone on a reused name or an attribute-only change is not acted on. Watch roots are held across volume lock, re-plug and junction boundaries, and a handle can be closed on a dead share while gates are held.
9) Long-lived process growth. Accumulated trees, _forcedVisible, _renames, icon caches, the 20k ask cap, glyph atlas space and per-GUID files only grow, and O(N^2) or whole-tree passes (colouring, edge disposal, the name filter, picker refilter) scale with session history.
10) Multi-canvas GPU sharing: shared atlases, the shaping queue and process-wide frame counters assume one canvas, so split view and multiple windows hit disposed views, dropped wake-ups and mutual icon eviction.
